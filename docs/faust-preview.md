## 本机运行

DSH服务运行于127.0.0.1:4320后，在网站目录执行：

    npm run dev:faust

访问 http://127.0.0.1:4321/faust/ ，点击“连接本机浮士德”。预览使用现有开发登录，消息会写入同一个Agent的实际会话。网站请求来源是web，不触发QQ消息投递。本机连接仅用于开发验证。

页面包括：对话/已有历史、短句依次展示、任务状态、动作过程、QQ绑定状态、登录过期/服务离线反馈和响应式布局。暂不提供账号绑定修改、外部动作审批或暂停/停止按钮，等待DSH相应语义验证完成。没有新建人设、没有迁入旧oh-my-pi。

## 对接实现

- src/pages/faust/index.astro：独立页面骨架。
- src/styles/faust.css：仅作用于浮士德页，复用主站颜色。
- src/scripts/faust/app.js：会话、聊天、同步和逐句呈现。
- src/scripts/faust/protocol.js：DSH 0.1实际字段与SSE解析。
- scripts/faust-preview.mjs：仅Astro开发服务器加载的本机代理，生产静态构建没有此服务。
- public/faust/config.json：公开配置，enabled=false。未启用时显示准备中，不访问本机地址、不匿名发消息。

代理只监听预览进程的loopback入口，检查客户端来源、Host及Origin并限制路径。不代理OneBot、平台账号动作或任务命令。后端CORS暂缺X-CSRF-Token，使用这条明确的本机开发链路联调，不修改DSH服务配置或放宽其生产权限。

适配当前实际返回：csrf_token位于session内；消息meta.utterances为字符串数组；事件为tool.action/task.state等且可能只含ID；并没有文档承诺的完整message.created流。因此收到事件后读快照，另每6秒同步一次。后端快照原子性问题仍由DSH修复，前端定期核对只是预览补偿，不构成无丢失保证。旧记录直接呈现，新助手回复按已有分句排队展示；不重写台词、不做字符打字动画。

所有内容以textContent渲染；不把模型文本当HTML。会话cookie由浏览器管理，不在localStorage持久化记录或token。网络失败保留草稿，不自动重新发送。重试相同草稿复用同一请求键；结果未知时阻止修改正文复用旧键。客户端退出关闭SSE并清空私有界面；后端流失效处理仍待DSH完善。

## 远程接入前

静态页面发布路径为 https://yourskenny.top/faust/ ，本次不改DNS。公开配置保持enabled=false，页面发布不代表远程Agent已经接通。启用远程服务前完成DSH登录验证、绑定、幂等、快照修复，补全CORS允许X-CSRF-Token；再由网站方设定HTTPS API base并启用公开配置。静态站的/faust/不包含私有对话数据，登录后才读取服务。

不以允许第三方cookie解决全部问题：两个HTTPS子域是跨origin但same-site，仍需精确CORS和正确会话配置。实际移动浏览器需单独验证。生产配置不能开启devLogin。

验证命令：npm test、npm run build。浏览器截图与交互证据放在忽略的output/playwright/目录；不得提交会话cookie、模型凭据或含私人聊天的自动化状态文件。
